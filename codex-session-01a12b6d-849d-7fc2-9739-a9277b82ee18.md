## 2. Intended DINOv3 pipeline

The architecture is:

```text
RGB frame
    │
    └──→ SAM3
             ↓
        Object masks
             ↓
        2D bounding boxes
             ↓
        Add bbox padding
             ↓
        Crop original RGB frame
             ↓
           DINOv3
             ↓
      Global image features
             ↓
       Object descriptor
             ↓
   One descriptor per object [N, D]
```

**Important architectural decision:**

We are deliberately using **bounding-box crops**, not full-frame patch features with mask pooling.

Each object crop is independently passed through DINOv3 to obtain one descriptor.

Do not recommend implementing mask pooling, mask-to-patch alignment, or spatial patch-grid reconstruction as requirements for this pipeline.

### C. Confirmed bugs and potential issues

**Confirmed from source inspection**

1. **Incomplete clipping can select unrelated image pixels.**  
   At `image_crop.py` lines 15–18, lower endpoints are only clamped against zero, and upper endpoints only against width/height. Negative upper endpoints survive.

   For an image width of 100, box `[-30, 10, -10, 20]` with zero padding becomes an x slice of `0:-10`. That selects most of the image despite the box being wholly outside it.

2. **Inclusive SAM3 endpoints do not directly match the crop slices.**  
   At zero padding, the maximum occupied row and column are omitted. Default padding does not reliably compensate, particularly for small objects. A one-pixel SAM3 box `[10, 10, 10, 10]` receives zero padding and produces an empty crop.

3. **Invalid boxes lack safe handling.**  
   Reversed or degenerate boxes can return empty crops. `NaN`, infinity, or incorrectly sized boxes can raise during unpacking or integer conversion, aborting `crop_bboxes()`.

4. **Integer conversion can erase small valid regions.**  
   `int()` truncates coordinates. Positive upper endpoints round inward; sufficiently small fractional boxes can collapse to zero width or height. The error is below one pixel per endpoint, but that is material for tiny objects.

5. **Tiny HWC crops can be misinterpreted by channel inference.**  
   `encode()` does not specify `input_data_format`. The installed [channel inference function](/home/ost/kth/DD2600/eai-project/.venv/lib/python3.13/site-packages/transformers/image_utils.py:288) chooses channels-first when both the first and last dimensions look like channel counts. An RGB crop with height 1 or 3 therefore has ambiguous layout and can be processed incorrectly.

6. **The proposed descriptor contract is not satisfied.**  
   Descriptors lack L2 normalization, NumPy conversion, validity flags, and stable batch rank. These are confirmed omissions, rather than evidence that CLS extraction itself is defective.

There is **no confirmed descriptor-shifting bug in an existing object wrapper**, because that wrapper does not exist. The crop list currently preserves positions until an exception occurs.

**Potential issues requiring validation**

- Viewpoint changes, occlusion, lighting, padding background, and similar-looking instances may reduce matching accuracy.
- Square resizing may affect descriptors of elongated objects.
- Very small crops may yield valid numerical descriptors with little useful object information.
- Float images already in `[0, 1]` would be rescaled again under the current defaults.
- Batch capacity, throughput, and repeatability depend on the execution environment.
- `eval()` disables training behavior, but does not by itself guarantee bitwise deterministic GPU results.

No incorrect model/input device transfer or incorrect CLS extraction was found. The demo’s `rgb.copy()` at line 56 appears unnecessary for ordinary inputs. Replacing `no_grad()` with `inference_mode()` would be optional optimization, not a required fix.

2. **Add `encode_objects()` to the existing `dino.py`.**

   Allocate `[N, D]` output and `valid[N]` first. Check embeddings for finite values and nonzero norms, L2-normalize valid rows, and scatter them into original positions. Keep invalid rows zero with `valid=False`. Return correctly shaped outputs without inference for empty or all-invalid inputs.

4. **Document output type and dtype.**  
   I recommend NumPy `float32` descriptors and NumPy boolean validity for the standalone interface, with normalization performed in float32. Conversion to the existing `Features.float16` storage contract can happen at its consumer.

   Retain the current model and CLS extraction while establishing crop correctness and matching quality.
